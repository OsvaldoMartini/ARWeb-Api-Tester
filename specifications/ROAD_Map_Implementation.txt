# Roadmap — React + TypeScript + Tauri API Testing Tool

## Important technical decision

Your target should be:

**React + TypeScript frontend**
**Node.js / TypeScript business engine**
**SQLite local database**
**Tauri executable wrapper**
**No C# business logic**

One clarification: Tauri itself is not a pure Node.js runtime. Tauri applications use a web frontend and a native shell; the backend side commonly uses Rust when needed. However, Tauri officially supports packaging a Node.js application as a sidecar, so the client does **not** need to install Node.js separately. This is the best approach for your goal: no C#, business logic in TypeScript/Node, final delivery as a Tauri `.exe` installer. ([Tauri][1]) ([Tauri][2])

---

# 1. Final Product Vision

Create a desktop application for non-technical clients to test APIs without using Postman, code, scripts, or technical configuration.

The application must allow the user to:

1. Import OpenAPI / Swagger files.
2. Automatically build an API catalog.
3. Organize APIs by business category.
4. Ask questions in natural language.
5. Generate test cases with AI.
6. Build visual no-code API workflows.
7. Execute tests against real APIs.
8. Execute tests against a local mock server.
9. Validate that no fake endpoint or field is invented.
10. Generate reports and exports.
11. Deliver everything as a Tauri Windows executable.

The strongest source architecture is the combination of Pilot 3 for the multi-agent architecture, Pilot 1 for the BotJob engine and full data model, and Pilot 2 for the mock server, floating AI prompt, and runtime services.

# 3. Recommended Technology Stack

| Area             | Recommended Choice                                           |
| ---------------- | ------------------------------------------------------------ |
| Desktop wrapper  | Tauri v2                                                     |
| Frontend         | React + TypeScript                                           |
| Build frontend   | Vite                                                         |
| UI library       | Tailwind CSS + shadcn/ui or MUI                              |
| State management | Zustand or Redux Toolkit                                     |
| Forms            | React Hook Form + Zod                                        |
| Backend runtime  | Node.js sidecar packaged with Tauri                          |

| ORM              | Drizzle ORM or Prisma                                        |
| OpenAPI parser   | `@apidevtools/swagger-parser`                                |
| HTTP execution   | `undici` or Axios                                            |
| Mock server      | Fastify                                                      |
| AI providers     | OpenAI, Anthropic, Gemini, Azure OpenAI, Ollama, Together.ai |

Tauri can bundle the desktop application into Windows installers using the Tauri CLI build command, and the Windows development environment requires Microsoft C++ Build Tools plus WebView2. ([Tauri][3]) ([Tauri][4])

# 5. Roadmap by Phase

## Phase 0 — Product Definition and Technical Baseline

**Goal:** Define the final product before writing code.

Deliverables:

```text
/specifications/PRODUCT_VISION.md
/specifications/FUNCTIONAL_REQUIREMENTS.md
/specifications/TECHNICAL_ARCHITECTURE.md
/specifications/DATA_MODEL.md
/specifications/SECURITY_MODEL.md
```

Decisions:

* The application will not use C#.
* The UI will be React + TypeScript.
* The business engine will be Node.js + TypeScript.
* Tauri will only package and expose native desktop capabilities.
* Rust inside Tauri must remain minimal and must not contain business logic.
* The Node sidecar will contain the API testing engine.

## Phase 5 — RealApiCatalogValidator

**Goal:** Implement the most important rule: no fake API usage.

This must be a non-bypassable TypeScript service.

Responsibilities:

```text
validateEndpointExists(endpointId)
validateMethodAndPath(method, path)
validateParameterExists(endpointId, parameterName)
validateOutputFieldExists(endpointId, jsonPath)
validateBotJobCommand(command)
validateAgentPlan(plan)
validateAiGeneratedBotJob(botJob)
```

This rule is the core trust mechanism across all three pilots. The final recommendations explicitly identify `RealApiCatalogValidator` as the single most important architectural invariant.

# 8. Final Recommendation

Build a **new TypeScript-first project**, not a direct conversion of the existing C# projects.

Use this strategy:

```text
Pilot 3 = architecture brain
Pilot 1 = API testing engine and database model
Pilot 2 = mock server and AI runtime UX
Tauri = final executable delivery
React = modern client interface
Node.js = all business logic
SQLite = local persistent storage
```

The final architecture should not contain C# code. The only non-TypeScript part should be the minimal Tauri native shell required to package and run the desktop application. Tauri can package the Node.js backend as a self-contained sidecar, so the client receives a normal desktop executable without needing to install Node.js manually. ([Tauri][2])
